## Identify rows with a primary key

A primary key uniquely identifies each row and does not allow NULL. A table has one primary key constraint, which may consist of one or more columns.

~~~sql
ALTER TABLE departments
ADD CONSTRAINT departments_pk
PRIMARY KEY (department_id);

ALTER TABLE employees
ADD CONSTRAINT employees_pk
PRIMARY KEY (employee_id);
~~~

Choose a key whose values are stable and unique. A primary key is a data-integrity rule, not just a display value.

## Connect tables with a foreign key

A foreign key requires a child value to match a referenced key, unless the child value is NULL and the column allows it:

~~~sql
ALTER TABLE employees
ADD CONSTRAINT employees_department_fk
FOREIGN KEY (department_id)
REFERENCES departments (department_id);
~~~

The referenced column must be backed by a primary key or unique constraint. Decide what should happen when a parent row is deleted. Without a delete rule, Oracle prevents deleting a referenced department until its employee references are handled.

## Add column and row rules

**NOT NULL** requires a value. **UNIQUE** rejects duplicate key values. **CHECK** validates a condition for each changed row:

~~~sql
ALTER TABLE employees
MODIFY full_name CONSTRAINT employees_name_nn NOT NULL;

ALTER TABLE employees
ADD CONSTRAINT employees_salary_ck
CHECK (salary >= 0);
~~~

A CHECK condition that evaluates to NULL is not false, so pair it with **NOT NULL** when missing values must be rejected. Add constraints with meaningful names so an error identifies the intended rule.

When adding a constraint to an existing table, existing rows must satisfy it. Inspect and correct data before applying the change.

## Generate identifiers with an identity column

An identity column asks Oracle to generate numeric values for inserted rows:

~~~sql
CREATE TABLE practice_tasks (
  task_id NUMBER GENERATED BY DEFAULT AS IDENTITY,
  title VARCHAR2(120 CHAR) NOT NULL,
  CONSTRAINT practice_tasks_pk PRIMARY KEY (task_id)
);
~~~

**GENERATED BY DEFAULT** allows a caller to provide an explicit value when needed. **GENERATED ALWAYS** is stricter and normally requires Oracle to supply the value. Choose based on whether manual identifiers are part of the data-loading design.

## Generate values with a sequence

A sequence is a separate database object that generates numeric values:

~~~sql
CREATE SEQUENCE practice_task_seq
  START WITH 1
  INCREMENT BY 1;

INSERT INTO practice_tasks (task_id, title)
VALUES (practice_task_seq.NEXTVAL, 'Review keys');
~~~

**NEXTVAL** obtains a sequence value. **CURRVAL** returns the current session's sequence value after **NEXTVAL** has been used in that session.

Sequence values are not guaranteed to be gap-free. Rollbacks, caching, and concurrent use can leave gaps. Use them for identifiers, not as a count of committed rows.
